# リアルタイム動画クライアント向け 使い方メモ(2026-09-04)

対象: realtime_video / realtime-narration-video 等、gateway(8630)経由で
LTX-2.5 の a2v を短サイクル生成するクライアント。
本メモは 2026-09-03〜04 のサーバ改修(commit 5a09603 / 3976b9e / b2b940e /
bf8fc13 / 1f24110)と実測に基づく。**数値はすべて実測**(288×384・81f・a2v・
実写アンカー + 実TTS音声、nvfp4-fast、RTX PRO 6000 96GB)。

---

## 1. 推奨リクエスト(コピペ用)

```json
{
  "backend": "ltx25",
  "mode": "a2v",
  "params": {
    "prompt": "<シーンプロンプト>",
    "width": 384, "height": 512,
    "num_frames": 81, "fps": 16,
    "steps": 4,
    "guidance_scale": 3.0,
    "seed": <seed>
  },
  "extra": {
    "upscale": false,
    "decoder": "vae",
    "modality_scale": 1.3
  },
  "asset_ids": ["<画像アセット>", "<音声アセット>"]
}
```

- `modality_scale` は「口が開かない」対策が必要なときだけ付ける(+0.7s)。
  不要なら外すのが最速。
- バックエンドの load は `preset: "nvfp4-fast"` のみで良い
  (NVENC p4 はプリセットに焼き込み済み。override 不要)。

## 2. 速度の期待値(サーバ生成、288×384・81f)

| 構成 | サーバ生成 |
|---|---|
| steps 8(従来) | 3.20s |
| steps 6 | 2.68s(−16%) |
| **steps 4** | **2.19s(−31%)** |
| steps 4 + modality_scale 1.3 | ~2.9s(推定。ガイダンス分 +0.7s@4step) |

- 解像度の寄与は小さい: 288×384 と 384×512 の差は **−0.35s のみ**。
  「解像度を下げても速くならない」と感じたら正しい —— 支配項はステップ数と固定費。
  品質が欲しければ 384×512 に戻してよい(+0.35s だけ)。
- 完了検知はクライアントの `JOB_POLL_INTERVAL=0.1` 前提(平均 +0.05s)。

## 3. 【重要】効かないパラメータ・過去の誤解の訂正

| 項目 | 事実 |
|---|---|
| `steps`(〜2026-09-04 朝まで) | **黙殺されていた**(蒸留8σ固定、全ジョブ 8/8)。「4steps で速くなった」は錯覚(実際は LLM/TTS とサーバ改修の効果)。**bf8fc13 以降は本当に効く** |
| `audio_modality_scale` | **a2v では完全 no-op**(音声予測にしか効かず、a2v は音声凍結)。同一 seed で出力が bit 一致することを実測済み。**+0.9s 払って効果ゼロ**なので外すこと |
| `audio_guidance_scale` | 同上の構造で a2v では実効なしの疑いが強い。使わない |
| `guidance_scale` | 蒸留経路では常に 1.0 固定(送っても無視) |

## 4. リップシンク(「WAV を渡しても口が開かない」)対策

原因: 閉口アンカー(前クリップ末尾)× 実写の静的プライア × 微細な口の動き、の
綱引きで、序盤ステップに「聞いているポートレート」モードへ確定してしまう。
実写で発症し 3D/アニメで出ないのは、口の動きの空間周波数の差。

対策の優先順(実測根拠つき):

1. **連鎖アンカーに「発話中(口が開いた)フレーム」を選ぶ** — コストゼロ。
   機構の根に直接効く。前クリップ末尾の無音区間フレームを避けるだけでよい
2. **`modality_scale: 1.3`** — 口領域の動き +27%、連鎖の継ぎ目 PSNR 無劣化
   (39.5dB)。コスト +0.7s@4step(値によらず 1.0 超なら同額)。
   **1.1/1.2 は同コストで効果の証拠なし(1.2 は 2seed とも悪化)。使うなら 1.3**
3. ~~conditions strength を下げる(0.85/0.7)~~ — 口は動くが**継ぎ目が壊れる**
   (PSNR 39.2→36.6/33.3dB、ズームドリフト)。連鎖用途では非推奨

比較素材: `backends/minimax-h3/outputs/ab_ref2va/cmp_mouth_probe.png`(strength/
modality 比較)、`cmp_steps_quality.png`(8/6/4step 品質)。

## 5. steps 4 の品質に関する注意

steps<8 は蒸留8σ列の間引き(先頭・末尾を含む等間隔)で、**蒸留の学習分布外**。
静止フレームでは 8/6/4 とも同一性維持・破綻なしを確認済みだが、時間方向の品質
(ジッタ・口パク精度)は実利用で判定すること。**ダメなら steps 6(2.68s)が保険**。
ログで `distilled sigma subsample: 4/8 steps` が出ていれば効いている。

## 6. サイクル(連投)の性質

mp4 encode(0.4s)は非同期化済みで、**前ジョブの encode 中に次ジョブの denoise が
走る**。ジョブ N+1 を N の completed を待たずに投入すればサイクルから encode 分が
消える(投入はキュー式で 409 にならない)。TTS が先に済んでいるなら即投入を推奨。
